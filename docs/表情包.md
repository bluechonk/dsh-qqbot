功能默认关闭（`stickers.enabled: false`）。图库为空时所有逻辑静默跳过。

## 实际使用步骤

1. 把图片放进 `~/.dsh-qqbot/stickers/`（可建子目录）
2. 写 `~/.dsh-qqbot/stickers.json`（格式见下），给每张图至少标 `mood`
3. 配置里把 `stickers.enabled` 设为 `true`
4. 重启宿主

## 与原始设计的差异

原始设计是暴露 `send_sticker` 工具让模型自己选图。**实现时改成插件自主配图**：

- qqchat 是**零工具**预设，工具用不了
- 插件在拿到回复文本后推断情绪、按规则挑图，更稳更便宜
- 不会因为模型「忘了调工具」而永远发不出表情

## 图库格式

文件位置：`~/.dsh-qqbot/stickers.json`

```json
{
  "version": 1,
  "stickers": [
    {
      "id": "s001",
      "file": "deepseek-chan/得意-原来是高等模型.png",
      "text": "原来是高等模型",
      "mood": "得意",
      "scene": "被夸",
      "strength": "light"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定标识，发送时用它定位 |
| `file` | 是 | 图片路径（相对素材目录） |
| `text` | 否 | **台词/描述，素材自带的原文最有价值** |
| `mood` | 否 | 情绪标签，见下表；缺了这张图永远选不中 |
| `scene` | 否 | 场景标签（被夸 / 摸鱼 / 干饭 …） |
| `strength` | 否 | `light` 或 `heavy`；同情绪下优先选 `light` |
| `vector` | 否 | 预留（L3 检索向量，本版未用） |

### 情绪标签取值

```
得意  嘲讽  委屈  卖萌  无语  开心  生气  疑惑
```

标签集**故意做小**。标签多了反而选不出来，也会让情绪判断更容易撞车。

## 时机规则

| 规则 | 默认值 | 为什么 |
|---|---|---|
| 连续 N 条纯文字后才允许配图 | 3 | 真人不是句句发表情 |
| 同一张图冷却 | 10 分钟 | 不连发同一张 |
| 判断不出情绪就不发 | — | 配错表情比不配更尴尬 |
| 优先选 `strength: light` | — | 同一情绪下轻一点更不容易翻车 |
| 极短回复用图**替代**文字 | ≤4 字 | 真人常只发一张图、零文字；每次都「文字+图」反而假 |

## 发送链路（已接）

用 SDK 的 `bot.sendImage(target, { localPath }, opts)` —— 内部封装了「上传富媒体 → 拿 `file_info` → 发送消息」，并把 `target.msgId` 透传下去（有 msgId 即被动回复，无则是主动消息）。

接入位置：`outbound.ts` 的 `send()`，流程是

```
正常回复 → 推断情绪 → 选图
  ├─ 选中且回复 ≤4 字 → 只发图（不发文字）
  ├─ 选中且回复较长   → 先发文字，再发图
  └─ 未选中          → 只发文字，文字计数 +1
```

三个必须守住的边界：

1. **SDK 没有 `sendImage` 时静默跳过**（旧版 SDK），不影响文字回复
2. **图发失败且刚才没发文字时补发原文**——否则用户什么都收不到
   （这个兜底参数一度传反，会导致静默丢消息）
3. **图库为空时整条路径不执行**，等于功能不存在

### 未验的地方

- 机器人是否有**发图片**权限（QQ 开放平台后台看）
- 单张图片大小上限
- 图片消息能否带文字（当前实现是「文字与图片分两条消息发」）

若图片权限没开，`sendImage` 会抛错，日志里能看到 `sticker send failed`，文字回复不受影响。
