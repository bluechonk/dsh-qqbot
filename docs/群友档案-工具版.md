## 一、先纠正一个前提

「加上可以用工具」听起来像在零工具的基础上**加一个东西**，其实不是。

摸了一遍实现：**工具是按插件挂载的**。

| 插件 | 作用 |
|---|---|
| `@deepseek-ai/dsh-tools` | 工具**注册表**（服务名 `tools`） |
| `@deepseek-ai/dsh-tool-bash` | 执行命令 |
| `@deepseek-ai/dsh-tool-fs` | 读写文件 |
| `@deepseek-ai/dsh-tool-web` | 上网 |

一个预设的 `plugins:` 列表决定挂哪些。`qqchat` 现在挂的是 `persona` + `compaction`，
所以「零工具」。

**关键判断：「零工具」不是目的，「不给危险工具」才是。**

所以正确的做法不是「给 qqchat 加一堆工具」，而是**只挂注册表、不挂危险的三个**：

```yaml
# cordis.patch.yml 的 preset-qqchat
plugins:
  - id: persona
    # ... 原文不动（除了下面 5.3 说的一句）
  - id: tools                          # ← 新增：只挂注册表
    name: '@deepseek-ai/dsh-tools'
  - id: compaction
    # ... 原文不动
```

于是：

- 机器人**依然不能**执行命令、读写文件、上网 → 「不会去动电脑」这条保证**不变**
- 但模型**能调用**插件注册的记忆工具

**安全边界靠「挂哪些插件」划，不靠「挂不挂工具」划。** 这是本方案最重要的一个判断。

## 二、要改哪里

| 文件 | 改动 |
|---|---|
| `cordis.patch.yml`（`preset-qqchat`） | `plugins` 里加一行 `tools`；persona 文案改一句（见 5.3） |
| `src/features/people/tools.ts`（新） | 注册两个工具；执行时反查当前会话 |
| `src/features/people/store.ts` | 复用现有 `memory.facts` 结构，新增 `remember`/`recall`/`forget` 的读写方法 |
| `src/commands/memory.ts`（新） | `/memory` 命令（看 / 删 / 清） |

**模型不需要知道 openid**：工具执行时用 `exec.agent` 反查当前会话
（`manager.findByAgent(exec.agent)` → `SessionRecord` → `scope`/`peerId`/`senderId`），
自动落到 `(appId, scope, openid)` 这个 key 上——与 `people.json` 现有索引一致。
`qqbot_send_file` 就是这么定位目标的，机制已验证。

## 三、工具集

只有两个。**工具定义是常驻 token**（每次请求都在 system prompt 里），所以越少越好。

### 3.1 `qqbot_remember` —— 记一条

```
name: qqbot_remember
description:
  记下关于**当前对话者**的一件事，供以后聊天时回想。
  只在对方明确告诉你关于他自己的信息时用（名字、称呼、喜好、经历、在忙什么）。
  不要记寒暄、不要记当次情绪、不要记你自己说的话。
parameters:
  text: 一句话，第三人称，例如「养了只叫豆豆的猫」。要短。
```

### 3.2 `qqbot_recall` —— 查

```
name: qqbot_recall
description:
  回想关于当前对话者的事。不确定他之前说过什么、或他提到「上次那个」时用它。
parameters:
  query: 可选关键词。不带则返回最近记住的几条。
```

返回带 id 的事实列表，让模型自己组织语言（**不是**直接回给用户）。

### 3.3 为什么不给 `forget()`

删记忆是**破坏性**操作，交给模型不合适——它可能因为一次不愉快就删掉对的记忆。
改由**主人**用 `/memory` 删（见 6.1）。

## 四、核心差异：注入 vs 检索

| | 无工具方案 | 本方案 |
|---|---|---|
| 谁决定记什么 | 插件（异步摘要） | **模型**（回合内调 `remember`） |
| 记忆怎么进上下文 | **每轮注入**最近 N 条 | **按需检索**（`recall`） |
| 常驻 token | 每条记忆都占 | 只有两个工具定义（约 200 token） |
| 额外 LLM 调用 | 每 N 轮一次摘要 | **零**（记在回合内完成） |
| 延迟 | 摘要异步，**不占回复时间** | **可能占**：调工具要多一轮模型往返 |
| 记错的风险 | 摘要幻觉 | 模型幻觉 |
| 规模 | 注入有上界，记忆多了会挤 | 可存很多，用时才取 |

**真正的取舍是「延迟 vs 判断力」**：

- 无工具方案把成本放在**后台**（异步摘要），用户感知不到，但模型对「记什么」没有发言权
- 本方案把成本放在**回合内**（工具调用），模型判断更准，但那一轮可能慢一次往返

## 五、必须解决的三个问题

### 5.1 模型会不会「忘了记」

`qqchat` 的 persona 写着「只回一到两句话、不主动提问、不主动揽活」——
这种极简人格**天然倾向于不调工具**。只加工具不改 persona，大概率一次都不会调。

**对策**：persona 里加一条（不是重写）：

```
他说到关于他自己的事（名字、喜好、经历、在忙什么）时，用 qqbot_remember 记一句。
别为此改变说话方式——记完照常回话。
```

### 5.2 模型会不会「记垃圾」

它会记「他今天心情不好」这种一次性状态，或者把寒暄也记下来。

**对策**（三层）：

1. 工具描述里明确「只记长期有用的」
2. 存储做**去重 + 封顶**（复用无工具方案第五节的规则：bigram Jaccard 去重 + 最多 8 条）
3. 每条带时间戳与来源，`/memory` 能看能删

### 5.3 「不读写文件」那句 persona 必须改

现有 persona 写着：

> 你此刻只是在陪主人闲聊，**没有任何工具可用：不执行命令，不读写文件**。

加了工具之后**这句就是假的**，而且模型可能因为这句而拒用工具。

**要改成准确的说法**，例如：

```
你手边只有一个记事本：能记下别人告诉你的关于他自己的事，也能翻看。
除此之外没有任何能力——不执行命令、不读写文件、不上网。
```

比直接删掉那句更好：**保留了安全边界的声明**，同时给出真实的工具范围。

## 六、顺带解锁的两件事

有了工具通道，两件在无工具方案里很别扭的事变得便宜。

### 6.1 `/memory` 命令（主人用）

```
/memory            看当前对话者的记忆
/memory forget 3   删掉第 3 条
/memory clear      清空
```

记忆是**不可再生数据**（`people.json` 的注释里就写了这句），出了问题必须能查能修。
无工具方案里这只能靠外部脚本（设计稿第十一节建议的 `qqbot-people` 技能）；
有工具方案里它就是一条普通命令，而且**和 `/whoami` 一样顺手**。

### 6.2 模型能「主动回想」

无工具方案的记忆是**被动注入**——每轮都塞，模型没得选。
有工具后可以让它在**觉得需要时**才查：对方说「上次那个事」，它自己会去 `recall`。
这更接近真人的记忆方式（想不起来才去翻）。

## 七、建议的落地形态：混合

两个方案不互斥。**最强的形态是混合**：

| 部分 | 用哪个 | 为什么 |
|---|---|---|
| 模型主动 `remember` | 本方案 | 判断准，零额外调用 |
| **每轮仍注入最近 2~3 条** | 无工具方案 | 保证「认得这个人」，不依赖模型想起来去查 |
| 插件侧周期摘要 | 无工具方案 | **兜底**：模型漏记的后台补上 |
| `recall` 深查 | 本方案 | 记忆多了以后按需取 |

**理由**：「模型想起来去查」这件事本身就不可靠。
陪聊场景里对方说一句「我猫又吐了」，模型如果没先 `recall`，就不知道那是「豆豆」——
而每轮注入 2~3 条能兜住这种最常见的场景。深查再交给 `recall`。

**别指望单靠工具**：`qqchat` 的人设是「随口一说」，它不会每句都先去翻记事本。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 模型不调工具 | persona 明确指令 + 每轮注入兜底 + 后台摘要兜底（第七节的混合） |
| 工具调用拖慢回复 | 工具执行本身是**本地文件写**（毫秒级），真正的成本是多一轮模型往返；可先观察 turn 耗时再决定接受度 |
| 模型记幻觉 | 工具描述限定「只记对方明确说过的」；`/memory` 可查可删 |
| 工具定义占常驻 token | 只有两个、描述简短（约 200 token） |
| 安全边界被误解成「放开工具了」 | 只挂 `dsh-tools`，**不挂** bash/fs/web；persona 保留「不执行命令」的声明；文档写明 |
| 与 `standard` 预设混淆 | 这是**给 `qqchat` 挂注册表**，不是把 `standard` 给 QQ 用——后者带全套危险工具 |

## 九、实施顺序

每一步都能独立验证、随时可停：

| 步 | 内容 | 可独立验证 |
|---|---|---|
| 1 | 预设挂 `dsh-tools`（不挂 bash/fs/web），确认模型能看到工具 | 群里问「你有什么工具」 |
| 2 | 注册 `qqbot_remember` + 存储写入（复用 `memory.facts`） | 说「叫我老王」→ 看 `people.json` |
| 3 | 注册 `qqbot_recall` + 去重封顶 | 单测 |
| 4 | persona 补「记事本」那段、改掉「没有任何工具可用」 | 群里实测：它会不会主动记 |
| 5 | `/memory` 命令（看 / 删 / 清） | 命令实测 |
| 6 | 每轮注入 2~3 条 + 后台摘要兜底（从无工具方案搬） | 重启后实测 |

**第 1 步是最小可验证切片**：只挂注册表、不加任何工具，先确认
「模型能看到工具、且看不到 bash/fs」——这一步通过，后面的设计才成立。

## 十、需要主人先定的一件事

**给 `qqchat` 挂 `dsh-tools`，意味着放弃「零工具」这个说法。**

安全性其实没变（不挂 bash/fs/web，机器人照样动不了电脑），
但「零工具」是之前明确写进 persona 与文档的**设计承诺**，不是随口一句。

要改的话这几处得一起改：

- `cordis.patch.yml` 的 persona 文案（5.3）
- `README.md`「零工具」相关表述
- `docs/内部机制.md` 的预设说明
- `docs/拟人化路线图.md` 里 M4/M5/视觉三处「因为零工具所以改了设计」的论证
  ——那三处的前提会变成「当时零工具」，需要标注时间

**这是设计承诺的变更，所以我不擅自决定。** 你点头我就按第九节那 6 步做。
