# 自主接话

让机器人在群里**不用被点名**也能有选择地接话——并且不让它变成刷屏的机器人。

> 实现状态：已落地（L1 词法门控 + L2 模型自决 + 冷却 + 每小时上限 + 判定日志
> + 时机特征 + 群友档案 + 防复读 + 冷场探测）。
> 仍未实现的部分见文末「边界与后续」。
> **注意：判定逻辑有单测覆盖，但从未在真实群里实测过**（见 [验收清单.md](验收清单.md)）。

## 一、目标与边界

**要解决的**：群里抛了个问题，但没 @ 任何人。传统 bot 必须被点名才回，于是大部分时间它是哑的；可如果放开来回，它会变成噪音。

**边界**：

- 只影响**群聊**；私聊一律照常回应，不受门控影响
- 只影响**未点名**的消息；被点名的一律必回，这条语义不打折
- 主动接话层**永远不能影响原有回话能力**——判定出错时一律放行，宁可多说一句，不可哑掉

## 二、整体设计

```
QQ 群消息
   │
   ├─ 4. historyBuffer        ← 挂在门控之前，未 @ 的消息也全量入内存历史
   ├─ 5. mentionGate          ← 自主接话开启时改 passthrough：只标记，不拦
   ├─ 5.5 proactiveGate       ← 真正的拦截点：L1 判定 + 冷却 + 每小时上限
   ├─ 6. contentSanitizer     ← 去 @marker、去表情标签
   │      …
   └─ 组装 user message → dsh agent ↓
          └─ L2：模型在回合内自决，插话不自然就回 [skip]
```

### 2.1 听见：historyBuffer 挂在门控之前

`historyBuffer` 配置 `recordOnSkip: true`，且**排在所有门控之前**。效果是群里每一条消息——包括没点名她的——都会进入上下文。

这样她才能理解「刚才大家在聊什么」，而不是凭空插一句。

> 群历史缓冲默认 10 条（`historyLimit`），回复后清空。

### 2.2 判断：L1 零 token 词法门控

不上模型，用一组可解释的句式/噪声特征给消息打分。目的是**挡掉明显不值得唤醒 AI 的消息**，而不是精准判断话题价值——精准判断交给 L2。

**打分规则**（基础分 0.5，加减后 clamp 到 [0,1]）：

| 特征 | 权重 | 词例 |
|---|---|---|
| 疑问句式 | +0.18 | 吗、呢、怎么、为什么、如何、哪、谁、是不是、有没有、能不能 |
| 求助词 | +0.14 | 帮我、帮忙、求助、请教、救命、怎么办、谁能帮、有人知道 |
| 呼朋唤友 | +0.10 | 有没有人、大家、请问、求问、在吗、有人在吗 |
| 提到本鲸 | +0.12 | 肥鱼、鲸鱼、大肥鱼、小鲸鲸、蓝鲸 |
| 灌水噪声 | −0.22 | 哈哈、嘿嘿、666、草、顶、沙发、前排、打卡、路过、围观、好耶 |
| @ 了别人 | −0.15 | 这轮对话的方向是别人，插嘴不自然 |
| 长文本 | −0.05 | 超过 80 字，多半不是闲聊 |

**直接不参与判定**的情况：

| 情况 | reason |
|---|---|
| 正文为空 | `empty` |
| 短于 `proactive.minLength` | `too-short(N)` |
| 纯表情/符号（无中日韩字符与字母数字） | `symbols-only` |

**语义纠正（不要写反）**

> **没被 @ 恰恰是她该主动接话的常态**，所以「没被 @」**绝不扣分**；
> 真正该扣分的是「这句 @ 的是别人」。

这是整个设计里最容易搞反的一点：早期实现把「未被 @」当扣分项，结果她永远不会主动开口。

分数 ≥ `proactive.minScore` 才值得唤醒模型。注意**分数高不等于「该接话」**，只意味着「值得让 AI 看看」。

### 2.3 开口：L2 模型在回合内自决

过了 L1 才会唤醒模型。模型此时看到的是「这条消息可能需要你」，最终回不回由它自己判断——觉得插嘴不自然，就回 `[skip]`，插件据此**不发送、也不计入回复**。

这就是「两段式接入 + 两级判断」：**接入**决定这条消息能不能进 AI，**判断**决定这条消息值不值得回。

### 2.4 判定结果的三种模式

判定结果写在 `ctx.state.proactive`：

| mode | 含义 | score | blocked |
|---|---|---|---|
| `mentioned` | 被点名，必回 | — | — |
| `chose` | 自主判定值得接话，已放行 | 有 | — |
| `observed` | 只记录，没接话 | 有 | `not-worth` / `cooldown` / `hourly-cap` |

`observed` 的消息**仍留在 historyBuffer 里**——她虽然没接话，但知道群里在聊什么，下次被点名时不会显得失忆。

## 三、配置

```yaml
# cordis.patch.yml
im-qqbot:
  proactive:
    enabled: true          # 总开关
    minScore: 0.55         # 放行门槛（0~1）
    cooldownMs: 120000     # 同群两次主动接话的最小间隔
    maxPerHour: 6          # 同群每小时上限，0 = 不限制
    minLength: 6           # 参与判定的最短文本长度
    observer: true         # 记录判定日志
```

这几项都可以在**设置页 → QQ 机器人**里改（`proactive` 整块在可编辑白名单里），改完自动重载。

> 注意：回复延迟的 4 个参数是**顶层**配置（`replyDelayMs` / `replyDelayPerCharMs` / `replyDelayJitterMs` / `replyDelayMaxMs`），**不在** `proactive` 块内。

## 四、频率控制

真人不会在群里连着插话，所以有两层约束（`src/features/proactive/cooldown.ts`）：

| 约束 | 配置 | 行为 |
|---|---|---|
| 同群冷却 | `cooldownMs` | 两次主动接话之间的最小间隔 |
| 每小时上限 | `maxPerHour` | 单群单小时主动接话次数封顶，0 = 不限制 |

状态存在**进程内存**里，重启归零——符合「聊天气氛」的直觉。每小时计数按 epoch 小时数分桶，跨天自动切换。

被冷却或被上限拦下时，判定结果记为 `observed`，`blocked` 分别是 `cooldown` / `hourly-cap`。

## 五、判定日志

`proactive.observer` 打开时，每次判定写一行 JSON 到 `~/.dsh-qqbot/proactive-scores.jsonl`：

| 字段 | 含义 |
|---|---|
| `gid` | 群 openid |
| `score` | 判定分 |
| `worth` | 是否过门槛 |
| `reason` | 命中的特征（如 `question+noise`） |
| `min` | 当时的门槛 |
| `mentionOthers` | 这条是否 @ 了别人 |
| `cooldownLeft` | 冷却还剩多少毫秒 |
| `hourlyUsed` / `hourlyFull` | 本小时已用次数 / 是否已满 |
| `chars` | 正文字数 |

**调参方式**：跑一天，看日志里被 `not-worth` 挡掉的那些消息长什么样，再调 `minScore`（或直接调词表权重）。门槛是唯一需要盯的旋钮。

## 六、代码位置

| 文件 | 职责 |
|---|---|
| `src/features/proactive/types.ts` | 类型定义（`ValueGate` / `ValueVerdict` / `ProactiveCandidate` / `ProactiveDecision`） |
| `src/features/proactive/lexical-gate.ts` | L1 词法打分（纯函数、确定性，便于单测） |
| `src/features/proactive/cooldown.ts` | 同群冷却 + 每小时上限 |
| `src/features/proactive/observer.ts` | 判定日志写入 |
| `src/middleware/proactive-gate.ts` | 门控中间件：串联 L1、冷却、上限，写 `ctx.state.proactive` |
| `src/gateway/middleware-setup.ts` | 中间件顺序（`historyBuffer` → `mentionGate` → `proactiveGate`） |

**扩展点**：`ValueGate` 是可替换接口（`evaluate(candidate)` 返回 `ValueVerdict | undefined`）。想换成本地嵌入或 LLM 判定，实现这个接口再换掉 `createLexicalGate` 即可，中间件不用动。返回 `undefined` 表示「实现不可用」，调用方按「未知 → 不拦截」处理。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 刷屏 | 冷却 + 每小时上限 + L2 模型自决，三层 |
| 误插话（不是跟她说） | 「@ 了别人」扣分 + L2 自决 |
| 判定实现有 bug 导致机器人变哑 | 门控内异常一律吞掉并放行（`falling through`） |
| 判定实现有 bug 导致刷屏 | 同上：放行意味着像普通群消息一样被处理，不会更吵 |
| 未开启时改变原有行为 | `proactive.enabled` 关闭时 `mentionGate` 保持原语义，门控直接 `next()`，行为逐字不变 |

## 八、验收标准

- [x] 未开启时，群聊行为与开启前**逐字一致**
- [x] 被 @ 必回（`mode: mentioned`）
- [x] 明显噪声（纯表情、「哈哈」）不唤醒模型
- [x] 疑问句能过门槛并唤醒模型
- [x] 冷却期内不再接话
- [x] 每小时上限生效
- [x] 判定日志可写、可读
- [x] 门控抛异常时放行，不影响回话
- [ ] 群里实测：真实群聊里接话自然度（需人工验收）

## 九、边界与后续

### 已实现（曾列在此处，现已落地）

| 能力 | 位置 | 说明 |
|---|---|---|
| **时机特征** | `features/proactive/activity.ts` | 群内热度（近 3 分钟消息数）、同一人连发、她刚说过话 → 加减分 |
| **群友档案** | `features/people/` | `people.json` 记昵称 / 别名 / 互动次数，注入一小段旁白 |
| **防复读** | `features/anti-repeat/` | 记自己最近 5 条发言前置进上下文（预防式，不额外跑模型） |
| **冷场探测** | `features/idle-topic/` | 判断「这个群是不是冷场了、该不该起话题」 |

### 仍未实现

- **出站主动发送**：定时开口、主动私聊——目前只会「回应」，不会「发起」。
  冷场探测已能判断时机，但**真的发消息被平台挡住**：
  QQ 被动回复只有 5 分钟窗口，冷场远超，只能走「主动消息」，
  而主动消息有按群按月的配额（详见 `findings.md` 的 R17）
- **话题类型分类**：情感/求助类接、事务/技术类不接——需要模型参与
- **长期记忆**：跨会话的话题摘要

详见 [拟人化路线图.md](拟人化路线图.md)。
