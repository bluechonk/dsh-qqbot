# 验收清单

功能已经堆了不少，但**大部分只在单测里验证过**。这份清单把「该看什么、在哪看、看不对怎么查」列全，照着走一遍即可。

## 准备

### 用脚本重启（推荐）

代码改动后**必须重启宿主进程**才能生效（插件从 `dist/` 经 `link:` 加载，
而 Node 有模块缓存，重载插件不保证换上新代码）。

```bash
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/restart-dsh.ps1
```

脚本会：优雅关闭 → 超时强杀全部相关进程 → 等彻底退出 → 重启 →
**等 `startup.log` 出现新的 `apply()` 记录**（这一条才真正证明插件加载成功）→ 报告监听端口。

> ⚠️ 必须在 DSH **之外**运行——它会杀掉 DSH 进程，包括正在跑的 AI 会话。
> 常用参数：`-NoWait`（启动后立即返回）、`-ReadyTimeoutSec 120`（冷启动慢时）。

### 手动重启

1. **完全退出** DeepSeek Harness（关窗口 ≠ 退出，Electron 常驻托盘）
2. 确认进程没了：`Get-Process 'DeepSeek Harness' -ErrorAction SilentlyContinue`（无输出才算干净）
3. 重新打开

### 确认插件活着

```bash
# 拿端口
$pids = (Get-Process 'DeepSeek Harness' -ErrorAction SilentlyContinue).Id
Get-NetTCPConnection -State Listen | Where-Object { $pids -contains $_.OwningProcess } |
  Select-Object -ExpandProperty LocalPort -Unique
```

```bash
# 期望 200 {"phase":"bound","appId":"..."}
curl http://127.0.0.1:<端口>/qqbot/im-qqbot/bind
```

数据目录：`~/.dsh-qqbot/`

## 一、基础连通

| 验什么 | 怎么做 | 期望 | 不对时看 |
|---|---|---|---|
| 私聊通 | QQ 私聊发「在吗」 | 有回复 | `startup.log` 有没有 apply() |
| 群聊通 | 群里发「大肥鱼」 | 有回复 | `proactive-scores.jsonl` 有没有记录 |
| 被 @ 必回 | 群里 @ 她 + 随便说点 | 必回 | 日志里 `decision=mentioned` |

> **完全没有日志** → 消息没到插件，是 QQ 平台没推（群消息权限或额度），代码侧无解。

## 二、自主接话与时机

| 验什么 | 怎么做 | 期望 |
|---|---|---|
| 该接的接 | 群里发「这个报错怎么解决啊」（别 @） | 大概率接 |
| 不该接的不接 | 连发「哈哈哈」「666」「打卡」 | 不接 |
| 别连珠炮 | 她刚说完话，立刻再抛一句 | 大概率不接（`bot-just-spoke`） |
| 别抢话 | 群里快速刷 20+ 条 | 不插嘴（`busy-group`） |
| 连发该接 | 同一个人连发 2~3 条没人应 | 更容易接（`consecutive-sender`） |
| 喊名字必应 | 刷屏中也喊「大肥鱼」 | 必应（名字压过一切时机特征） |

**怎么确认判定原因**：看 `~/.dsh-qqbot/proactive-scores.jsonl`，每行有 `score` / `reason` / `recentMessages` / `consecutiveSameSender` / `sinceBotSpokeMs`。

```bash
# 看最近 10 条判定
tail -10 ~/.dsh-qqbot/proactive-scores.jsonl
```

## 三、拟人化

| 验什么 | 怎么做 | 期望 |
|---|---|---|
| 不秒回 | 观察回复到达时间 | 有停顿感，但不至于等到烦躁 |
| 会沉默 | 多聊几句 | 偶尔回 `[skip]`（即完全不发消息） |
| 不复读 | 连续问类似的问题 | 说法不重样 |
| 记得称呼 | 群里说「叫我老王」，之后再看 | 会叫「老王」 |
| 人格一致 | 随便聊几句 | 傲娇、≤40 字、不分段、不写括号动作 |

**群友档案检查**：

```bash
cat ~/.dsh-qqbot/people.json
# 期望：能看到 openid、name、aliases、count
```

> 档案按 `appId|群或私聊|openid` 隔离——同一个群被两个机器人加，档案各自独立。

## 四、设置页

| 验什么 | 怎么做 | 期望 |
|---|---|---|
| 保存能成功 | 改任一开关 → 保存 | 提示保存成功，不再报错 |
| 思考模式 | 下拉选「关闭」→ 保存 | 保存成功，回复变快 |
| 命令权限 | 「命令权限」分组填自己的 openid → 保存 | 保存成功；`/whoami` 显示「主人」 |
| 默认值正确 | 看面板初始值 | 要求 @ 关、流式关、工具结果关、自主接话开、权限校验开 |

> 若报「不支持的字段: xxx」→ 宿主跑的是旧代码，重启。
> 若报「无法定位 profile 目录」→ 是新 bug，回报。

## 五、命令

| 命令 | 期望 |
|---|---|
| `/model` | 列出可用模型（可点击） |
| `/model <provider>/<model>` | 切换成功，上下文保留 |
| `/new` | 开新会话 |
| `/preset` | 列出可用 preset 并标出当前（默认 qqchat） |
| `/preset <id>` | 切换成功并重建会话，上下文保留 |
| `/whoami` | 返回自己的 openid 与权限（所有人可用） |
| `/bot-status` | 显示当前会话状态 |

**权限**：除 `/whoami` / `/bot-ping` / `/bot-version` / `/bot-help` 外，命令都要求管理员身份。
让**非管理员**账号发 `/model`，应回「只有主人能执行这个命令」。

## 七、排障速查

| 现象 | 先查 |
|---|---|
| 完全不回 | `startup.log`（插件起来没）→ `proactive-scores.jsonl`（消息到了没）→ `middleware-drops.jsonl`（是不是被链上丢了） |
| 只回私聊不回群 | 群的推送权限；`raw-events.jsonl` 有没有群消息 |
| 发两条只回一条 | `middleware-drops.jsonl` 找 `kind=merge`（并发合并把两条并成一轮） |
| 回复慢 | 模型耗时 vs 目标延迟；`replyDelayMs` 调低或设 0 |
| 觉得太吵 | `proactive.minScore` 调高（0.55 → 0.7）、`proactive.maxPerHour` 调低 |
| 觉得太闷 | `proactive.minScore` 调低、`proactive.maxPerHour` 调高 |
| 命令被拒 | `admin.openids` 是否填了；`/whoami` 看权限 |
| 设置页存不上 | 重启宿主；仍不行回报（附报错原文） |

## 八、日志位置总表

```
~/.dsh-qqbot/
├── startup.log              # 插件启动留痕（失败原因）
├── proactive-scores.jsonl   # 自主接话判定（分数/理由/时机特征）
├── middleware-drops.jsonl   # 中间件链丢弃留痕（drop/denied/merge）
├── raw-events.jsonl         # 未知网关事件（探测平台推不推某类事件）
├── people.json              # 群友档案
├── stickers.json            # 表情包图库元数据
├── stickers/                # 表情包素材（自备）
└── model-prefs.json         # per-peer 模型与预设偏好（偏好/实际 preset 分开）
```

排查顺序：`startup.log` → `proactive-scores.jsonl` → `middleware-drops.jsonl`
→ `people.json` → 会话事件日志。前三个能定位绝大多数「消息到了但机器人没反应」。
