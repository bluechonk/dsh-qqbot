## 七、这个项目最大的风险类别：静默失效

已经修过 **7 个**「不报错、不掉线、测试全绿，只是功能悄悄不对」的 bug：

| bug | 症状 |
|---|---|
| 流式路径绕过 `send()` | 开流式后防复读/表情包/时机特征全部失效 |
| `turn/end{blocked}` 不处理 | 机器人彻底哑掉，日志干净 |
| 会话跑错 preset | 人格不生效、工具泄漏，但它「能回话」 |
| 档案写盘被节流吞掉 | 密集群聊时关掉宿主就丢别名 |
| `reasoningEffort` 无条件注入 | 模型不支持时整轮失败，只留一句报错 |
| 中间件链静默丢弃 | 门控有记录，档案与会话日志纹丝不动 |
| preset 偏好与实际值混用 | 切换后被自己的一致性检测丢掉 |

**写降级逻辑时务必留痕。** 降级本身没错，但「功能没了没人知道」是最贵的 bug。

**审查代码时的重点**：找 `catch {}`、`?? 默认值`、`if (!x) return` 这类静默路径，
问一句「这里失败的话，有人会知道吗」。

## 八、几条踩过坑的硬知识

### 平台限制

| 限制 | 影响 |
|---|---|
| 被动回复只有约 5 分钟窗口 | 冷场起话题只能走主动消息，而主动消息有按群按月配额 |
| 图片消息只透传 `msg_id`，**忽略 `eventId`** | 按钮互动触发的回复不能配图（会退化成主动消息） |
| 群消息推的是 **openid**，不是群号 | 算 sessionId 时别拿群号 |
| **平台不告诉机器人谁是创建者** | 主人身份必须显式配置 |

### DSH 内部

| 知识 | 说明 |
|---|---|
| `agents.resume()` **改不了 preset** | 只接受 `agentOptions` 与 `setup`，没有 preset 参数 → 切换必须重建会话 |
| `sessions.fork()` 返回**子会话对象**，不是 `{events}` | 按旧契约读 `.events` 会得到 undefined；且它每次调用都真建一个会话 |
| 要事件快照就读 `agent.session.snapshotEvents()` | DSH 官方读法 |
| `reasoningEffort` 是**硬校验** | 模型没有 reasoning 能力时，传任何值都抛 `UNSUPPORTED_REASONING_EFFORT` |
| `listModels` **不带**能力信息 | 只有 `resolveModelInfo(provider, model)` 有 |
| 会话文件是**多帧追加** zstd | Node 的 `zstdDecompressSync` 只解第一帧，必须按魔数 `28 B5 2F FD` 切帧 |
| 会话 id = `sha256(sessionKey)` 按 8-4-4-4-12 切分 | 可由 sessionKey 直接算出 |
| `ctx.stopReason` **可读** | SDK 中间件 `stop(reason)` 的原因能被下游读到，是丢弃留痕的基础 |
| **`scoped.effect(fn)` 的返回值才是销毁器** | 在回调体里调用 `dispose()` 等于**注册完立刻注销**——路由静默消失、请求全 404，且单测（用假 webServer）抓不到。正确写法是 `return () => { dispose() }` |

### 零工具预设的约束

`qqchat` 预设**不挂任何工具**。任何「让模型做决定」的功能都要先确认
**它在当前预设下有没有通道**。已因此改过两个设计：

| 功能 | 原设计 | 实际 |
|---|---|---|
| M4 群友档案 | 给模型工具「记住他」 | 无通道 → 只能本地启发式抽别名 |
| M5 表情包 | `send_sticker` 工具让模型选图 | 无通道 → 改为插件自主配图 |

### 并发合并（merge）

`concurrencyGuard` 用 `merge` 策略：**同一 peer 在上一个回合处理期间到达的消息，
会被合并成一轮**（内容用换行拼接，不丢）。所以「连发两条只回一条」是设计如此，
`middleware-drops.jsonl` 的 `kind=merge` 会记录合并了几条。
