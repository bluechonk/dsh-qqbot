## 四、待做的工作

### Phase 28：preset 支持切换（默认仍是 qqchat）

**主人明确要求**：preset 不再写死，默认 `qqchat` 但支持切换为其他模式。
这**反转**了早先「固定 qqchat、不支持切换」的决定。

**现状**：`getEffectivePresetByKey()` 硬编码返回 `FIXED_PRESET_ID`；
`/preset` 命令明确拒绝一切切换请求。

**设计要点（已调研，直接照做）**：

1. `getEffectivePresetByKey(key)` → `prefs.getPreset(key) ?? config.preset ?? 'qqchat'`
2. **必须区分两个概念**（当前被混用，这是最容易踩的坑）：
   - `prefs.presets` = **用户选的** per-peer preset 偏好（恢复它原本的语义）
   - `prefs.sessionPresets` = 会话**实际创建时**用的 preset（Phase 25 的一致性检测用）

   混用会导致「刚切换完就被自己的一致性检测丢掉」。
3. `/preset` 命令：用 `agentPresets.list()` 列出可用 preset、显示当前、支持切换
4. **切换必须重建会话**：`agents.resume()` **改不了 preset**（已实测证实），
   所以切换 = 持久化偏好 + `rebuildSession`
5. Phase 25 的一致性检测（`session-manager.ts` 里比较 `recordedPreset !== FIXED_PRESET_ID`）
   要改为与**生效 preset** 比较，而不是与常量比较
6. `/preset` 归入**管理员专用**命令（切到 `standard` 会带来 pwsh 全套工具，是安全相关操作）

### 新发现的问题（未修）

主人实测时发了**两条**消息，只有第一条到了 agent：

| 时间 | 判定日志 | `people.json` | 会话事件日志 |
|---|---|---|---|
| 11:12:05 | `mentioned` | 更新 `count=1` | 更新 |
| 11:13:35 | `mentioned` | **没更新** | **没更新** |

`people.touch()` 在 `handleInbound` **内部最开头**，所以
「门控有记录 + 档案没更新」唯一的意思是：**消息在门控之后、agent 之前被丢掉了**。

嫌疑最大的是 `concurrencyGuard` 与 `rateLimiter`。
**建议做法**：给中间件链加**统一的丢弃留痕**——当前只有门控会记日志，
其余关卡静默丢弃。这正是本项目最大的风险类别（见第七节）。

## 七、这个项目最大的风险类别：静默失效

已经修过 **6 个**「不报错、不掉线、测试全绿，只是功能悄悄不对」的 bug：

| bug | 症状 |
|---|---|
| 流式路径绕过 `send()` | 开流式后防复读/表情包/时机特征全部失效 |
| `turn/end{blocked}` 不处理 | 机器人彻底哑掉，日志干净 |
| 会话跑错 preset | 人格不生效、工具泄漏，但它「能回话」 |
| 档案写盘被节流吞掉 | 密集群聊时关掉宿主就丢别名 |
| `reasoningEffort` 无条件注入 | 模型不支持时整轮失败，只留一句报错 |
| 中间件链静默丢弃 | 门控有记录，档案与会话日志纹丝不动（**未修**） |

**写降级逻辑时务必留痕。** 降级本身没错，但「功能没了没人知道」是最贵的 bug。

**审查代码时的重点**：找 `catch {}`、`?? 默认值`、`if (!x) return` 这类静默路径，
问一句「这里失败的话，有人会知道吗」。

## 八、几条踩过坑的硬知识

### 平台限制

| 限制 | 影响 |
|---|---|
| 被动回复只有约 5 分钟窗口 | 冷场起话题只能走主动消息，而主动消息有按群按月配额 |
| 图片消息只透传 `msg_id`，**忽略 `eventId`** | 按钮互动触发的回复不能配图（会退化成主动消息） |
| 群消息推的是 **openid**，不是群号 | 算 sessionId 时别拿群号 |
| **平台不告诉机器人谁是创建者** | 主人身份必须显式配置 |

### DSH 内部

| 知识 | 说明 |
|---|---|
| `agents.resume()` **改不了 preset** | 只接受 `agentOptions` 与 `setup`，没有 preset 参数 |
| `sessions.fork()` 返回**子会话对象**，不是 `{events}` | 按旧契约读 `.events` 会得到 undefined；且它每次调用都真建一个会话 |
| 要事件快照就读 `agent.session.snapshotEvents()` | DSH 官方读法 |
| `reasoningEffort` 是**硬校验** | 模型没有 reasoning 能力时，传任何值都抛 `UNSUPPORTED_REASONING_EFFORT` |
| `listModels` **不带**能力信息 | 只有 `resolveModelInfo(provider, model)` 有 |
| 会话文件是**多帧追加** zstd | Node 的 `zstdDecompressSync` 只解第一帧，必须按魔数 `28 B5 2F FD` 切帧 |
| 会话 id = `sha256(sessionKey)` 按 8-4-4-4-12 切分 | 可由 sessionKey 直接算出 |

### 零工具预设的约束

`qqchat` 预设**不挂任何工具**。任何「让模型做决定」的功能都要先确认
**它在当前预设下有没有通道**。已因此改过两个设计：

| 功能 | 原设计 | 实际 |
|---|---|---|
| M4 群友档案 | 给模型工具「记住他」 | 无通道 → 只能本地启发式抽别名 |
| M5 表情包 | `send_sticker` 工具让模型选图 | 无通道 → 改为插件自主配图 |
